# Daily CobyTransit maintenance

The published Site remains owner-private. Do not change its audience. No credentials belong in this document, source files, source archives, logs or task reports.

1. Obtain current Site state with `get_site`. Confirm the owner-only access policy (only owner, no editors/viewers/groups) before any write. Stop and report if audience or ownership changed. Use the returned service-access credential only in the `OAI-Sites-Authorization: Bearer …` request header to that exact Site origin. Never forward it to feed hosts or redirects.
2. Obtain current source access with the Sites credential tool, open through the source helper, and read this file. Source access and Site service access are separate. Do not assume credentials from a past run still work.
3. GET `/api/snapshot`, retain its `meta.sha256` as the optimistic-write revision and validate the returned data. Download the fixed 511NY feed through `python3 scripts/import-gtfs.py` in the source checkout. Run `node scripts/check-data.mjs`. Do not bypass validation or the fixed-origin/size limits. Do not push or publish merely to update runtime data.
4. Review official RideSCPT route pages, notices, holiday policies and SUNY calendar. Confirm the specific service-day notice, dates, pickup/drop-off corrections and whether the student eligibility calendar was updated. Do not infer student free rides, missing service, live tracking or reservation confirmation. If a new source conflict affects a changed schedule, retain the existing runtime snapshot and report what needs review.
5. If the new feed is valid and material changes are corroborated by official pages, POST `/api/snapshot` with JSON `{ "snapshot": <validated imported JSON>, "expectedSha256": <current runtime hash>, "review": {"checkedAt": <current ISO timestamp>, "status": "current" or "needs-review", "notes": [<brief source-backed notes>]} }`. Use `needs-review` for unresolved published-source conflicts even when the feed itself has not changed. When official notices change, include an optional `review.notices` array of `{tag,title,body,url}` objects using only the existing official agency source URLs; this updates the displayed notices with the data and does not require a code release. Keep the source conflict warning unless the new primary source resolves it. The runtime independently checks the upstream ZIP digest, limits, schema, dates, references and calendar coverage; then persists the approved JSON atomically in R2. It never accepts arbitrary fetch URLs. Repeating a run is safe; a conflicting revision returns 409 and requires a fresh review.
6. GET `/api/snapshot` again. Confirm SHA, review timestamp, coverage and counts. Report changed schedules, approaching expiration (under 14 days), inaccessible sources or validation errors. Do not claim that this source check confirms actual bus operation.

Retries: use bounded timeouts. On upstream failure, validation failure, 409, or unavailable access/storage, retain the last working dataset; explain the failure and let the next scheduled run retry. Do not create duplicate schedules, rotate unrelated credentials, or replace known service rules with guesses.

The static source snapshot stays available as a fallback and in source downloads. Runtime data updates are independent of code releases. Any future public Site launch requires disabling this private maintenance writer or replacing the hosting access boundary with explicit server-side writer authorization first.
